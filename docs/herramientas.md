# Herramientas, Comportamientos y Pitfalls

## Reglas Generales de Tools
- **Errores:** Las tools deben retornar `ToolResult` (`success=False` si fallan) en lugar de lanzar excepciones. `FunctionTool.run()` normaliza los valores que no son `ToolResult` a `ToolResult(success=True, content=str(result))` (`app/core/harness/tool.py`). Si una tool lanza, `AgentLoop._execute_tool()` lo captura y construye `ToolResult(success=False, error="Error inesperado: …")` (`app/core/harness/loop.py`); el fallo se devuelve al modelo como `Error: … (Reintento n/3…)` y, tras 3 fallos, como `[SISTEMA: La herramienta … falló 3 veces…]` (`loop.py`).
- **Permisos:** `PermissionGate` pide confirmación (`y/a/n`) para `read_file`, `read_text_file`, `list_dir`, `list_directory`, `write_file`, `edit_file` y `bash` (y para cualquier tool sin política explícita; sin callback `ask_user`, deniega). La respuesta `a` guarda la firma en `session_allowed` (`.harness/permissions.json`) y la auto-aprueba en futuras llamadas (`app/core/harness/permissions.py`). Los subagentes derivan un gate hijo que comparte `session_allowed` y `ask_user` con el padre (`PermissionGate.child()`), por lo que esa aprobación también aplica al delegar. Para `write_file` y `edit_file` el modal muestra un diff: el de `edit_file` se calcula aplicando `edits` sobre el contenido actual, por lo que `oldText` debe existir y no estar vacío.
- **MCP:** Configurados en `mcp_config.json`. `MCPClient.connect()` reintenta 3 veces con backoff exponencial (`tenacity`) y timeout `MCP_CONNECT_TIMEOUT=10`; si falla la conexión inicial, la TUI escribe `❌ Error conectando MCP <nombre>: …` en el chat (`app/tui/app.py`). Las tools se registran con prefijo `mcp_<servidor>_` (`app/mcp/client.py`) y `call_tool` usa `TOOL_TIMEOUT=30s` (`client.py`). Si una tool falla en ejecución, `MCPToolProxy` reconecta y reintenta una vez (`client.py`).
- **Skills:** Se cargan de `.agents/skills/<name>/SKILL.md`. Se pueden invocar con la tool `load_skill` o con la sintaxis `@name` (tiene autocompletado).
- **Sessions:** `SessionManager` guarda en `.harness/sessions/<id>.json` (`settings.sessions_dir`) y carga la última sesión automáticamente al inicio. `/session new` guarda la sesión actual, crea una nueva, limpia el contexto (conservando el system prompt) y reinicia los contadores de reparación (`app/tui/commands.py`).
- **Comandos TUI:** `/model [nombre]` y `/provider [nombre]` son independientes: el primero cambia el modelo (`get_llm(provider, model=...)`) y el segundo, el proveedor (`commands.py`). `/compact [estrategia]` guarda la estrategia previa de `ContextManager` y la restaura al terminar (`commands.py`).
- **Memory:** El backend por defecto es `sqlite` → `.harness/memory.db` (`DATA_DIR/memory.db`; `app/core/config.py`), no `summary.md` (ese archivo solo aparece con el backend `files`). `MemoryStore.preamble()` se inyecta bajo `[Long-term memory]` en el System Prompt. Tools: `memory_save`, `memory_recall`.
- **Contexto del System Prompt:** `AGENTS.md` contiene reglas operativas (se cumplen estrictamente) y se lee junto con `tasks/actual.md`; la memoria añade su `preamble()`. El prompt describe solo esos dos bloques como BACKGROUND CONTEXT («the task list in tasks/actual.md and long-term memory»); `docs/` y `checks/` **no** se leen ni se inyectan: `AGENTS.md` indica consultarlos con tools cuando hacen falta (`app/tui/app.py`).

## Comportamientos Específicos (Pitfalls)
- **Prompt Caching:** `OpenAICompatibleProvider` inyecta `cache_control: {"type": "ephemeral"}` en el mensaje `system` si `ENABLE_PROMPT_CACHING=True` y ese mensaje tiene contenido `str`; no hay comprobación de soporte por modelo (`app/core/llm/providers/openai_provider.py`).
- **Safe Split Point:** La estrategia de compactación nunca corta un mensaje `tool` de su `assistant` correspondiente.
- **Streaming:** `AgentLoop.stream()` yieldea `AgentEvent(type, data)` (`app/core/harness/events.py`), no chunks de texto planos: los tipos son `text_chunk`, `tool_start`, `tool_end`, `result` y `error` (`loop.py`). La TUI consume esos eventos y renderiza el texto como Markdown en tiempo real. Timeout de 300s (`LLM_STREAM_TIMEOUT`) aplicado con `asyncio.timeout` en la TUI y en el loop (sin crear Tasks nuevos, para no romper el contexto de OTel/Langfuse). El provider ya no envuelve `create()` en `wait_for` y maneja errores 503 sin crashear (`app/core/llm/providers/openai_provider.py`).
- **Atajos TUI:** `Ctrl+U` limpia el input y los adjuntos vía `App.action_clear_input()`, que es **síncrono** (no llevar `await`, o lanza `TypeError`).
- **Multimodal:** Imágenes pegadas como Base64 (`data:<mime>;base64,...`): `image/png` para `.png` y `image/jpeg` para `.jpg/.jpeg/.gif/.webp` (`app/tui/app.py`). `FileAwareInput` intercepta el pegado de archivos para que no se escriban como texto. La vista previa usa `HalfcellImage` si `TERM_PROGRAM=WarpTerminal`; si no, `TerminalImage` (`app.py`). Para documentos, `read_document` extrae texto de PDF/DOCX/XLSX/PPTX, limita la salida a `MAX_DOCUMENT_CHARS=15000` con el aviso `[DOCUMENTO TRUNCADO]` y rechaza otros formatos (`.doc`, `.xls` y `.ppt` no son extraíbles; `app/tools/documents.py`).
- **Hooks de Bash:** Si un comando contiene `capture_snapshot.py`, inyecta automáticamente `--tools observations.json` para que la skill `agent-harness-explorer` funcione.
- **Pricing:** Usa `PricingProvider`. OpenRouter consulta API con caché en `.harness/pricing_cache.json` (TTL configurable). OpenAI/Groq leen `pricing.json`. El comando `/cost` muestra el gasto.
- **Rich Rendering:** `RichMessage` parsea bloques ```table, ```tree y ```json y los renderiza con Rich.
- **Flujo de Agentes:** El panel de debug (F1) muestra un `Tree` con el flujo en tiempo real (`start`, `end`, `handoff`).

## Observabilidad, Crítico y Skills
- **Langfuse:** Dependencia `langfuse>=5.2.0` (`pyproject.toml`). Se activa solo con `LANGFUSE_PUBLIC_KEY` y `LANGFUSE_SECRET_KEY` (`LANGFUSE_HOST`, si se da, o `https://cloud.langfuse.com` por defecto; `loop.py`). `AgentLoop.stream()` crea una generación `agent_stream` y la actualiza con salida, pasos, herramientas, `usage_details` (prompt/completion/total tokens) y `cost_details` (`loop.py`); timeouts y excepciones también se registran.
- **Auto-reflexión del crítico:** `CriticTool` (`app/tools/critic.py`) usa el LLM de `A2A_REVIEWER_MODEL` (o el modelo del proveedor si está vacío) para revisar la respuesta contra las reglas inyectadas al arranque (`AGENTS.md` y `tasks/actual.md`). Si responde `REJECTED: …`, el loop inyecta el motivo como feedback del sistema y reintenta hasta 2 veces, con avisos `⚠️` en el chat (`loop.py`). La TUI detecta el marcador `is_correction_marker`, retira el widget Markdown anterior y redibuja la respuesta corregida (`app/tui/app.py`).
- **Skill `token-budget-guard`:** Instalada en `.agents/skills/token-budget-guard/SKILL.md`. Monitoriza el gasto en tokens, aplica presupuestos configurables en `.harness/token-budget-guard/budget-config.json`, alerta al superarlos y sugiere modelos más baratos o prompt caching.
- **Rutas (`DATA_DIR`):** `DATA_DIR` (por defecto `.harness`) centraliza `memory.db`, `vector.db`, `memory/`, `logs/`, `sessions/`, `permissions.json` y `pricing_cache.json` (`app/core/config.py`).
